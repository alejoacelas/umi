Where panes live

Prototypes for comment c11 in DESIGN-primitives.md: the places a pane can be, five ways to show hidden panes, and the visual channels Umi has to work with. Syntax is illustrative. Content in the mock windows is made up. Next: Resurfacing a hidden pane, the transitions when one comes back.

1. Four places a pane can be

Every pane is in exactly one place. Its program keeps running in all four (in "closed" only for 60 seconds). umi ls reports it as place.

On show

Has its own rectangle in the tab's split layout. The focused one has the cyan line on its top edge.
umi split right
umi pane focus P

{"id":"7f3a","place":"shown",
 "focused":true}

Stacked

Shares a rectangle with other panes; a strip on top names them and one is on show. ⌘[ ⌘] switch.
umi pane move P --to Q --stack

{"id":"7f3a","place":"stacked",
 "stack":["91c0","7f3a","a2e4"]}

Hidden

Belongs to its tab but takes no space. Any pane kind. Optionally comes back by itself when a condition holds.
umi pane hide P \
  --until 'agent.done=false'
umi pane show P

{"id":"7f3a","place":"hidden",
 "tab":"c41d",
 "until":"agent.done=false"}

Closed (reopenable)

Gone from the layout; programs keep running for 60 s so ⇧⌘T can bring it back where it was.
umi pane close P
umi reopen

{"kind":"pane","place":"closed",
 "expires_in":42}

2. Five ways to show hidden panes

The same window in each option: tab website has five panes, two on show and three hidden; tab impact-ops has one hidden agent. "Simulate" makes the hidden deploy-check agent end its turn without Status: done, so it should come back.

1–5 option · S simulate · R reset · H hide focused pane · O overview (option E) · click a pane to focus it · click any hidden item to show it

3. Visual vocabulary

Every channel Umi can use to say something about a pane or tab, from quietest to loudest. The rule so far: the quietest channel that still gets noticed when it matters.
